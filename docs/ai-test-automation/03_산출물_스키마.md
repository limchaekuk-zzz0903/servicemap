# 산출물 스키마

사내 AI에 단계 프롬프트를 보낼 때 이 문서를 함께 첨부합니다. 모든 단계 산출물이 ID로 서로 연결되므로 형식을 지키는 것이 중요합니다.

```
screen_catalog.json ─ screen_id ─┬─ elements/<screen_id>.json ─ element_key ─┬─ testcases/*.json ─ tc_id ─ tests/*.py
                                  └─ transitions.json (entry, edges)          └─ pages/*.py (Page Object)
```

## 공통 규칙

| 항목 | 규칙 |
|---|---|
| `screen_id` | `SCR_` + 대문자 스네이크. 예: `SCR_SETTINGS_MAP` |
| `element_key` | `<screen_id>.<소스상 id 또는 testTag>`. id가 없으면 `<screen_id>.anon_<짧은설명>` |
| `tc_id` | `TC_<영역>_<3자리>`. 예: `TC_FAVORITE_001` |
| `evidence` | `"상대경로:라인"` 문자열 배열. 비어 있으면 안 됨 (UNKNOWN 항목 제외) |
| `confidence` | `explicit`(코드에 명시) / `inferred`(추적·추론) |
| 미확인 값 | 문자열 필드는 `"UNKNOWN"`, 해당 없음은 `null` |
| `safety` | `SAFE` / `CAUTION`(되돌릴 수 있는 데이터 변경) / `BLOCKED`(조작 금지) |
| 메타 | 모든 JSON 파일 최상단에 `meta` 객체 포함 |

```json
"meta": {
  "app_version": "11.2.0",
  "commit": "a1b2c3d",
  "generated_at": "2026-11-06",
  "generated_by": "P2",
  "scope": "검색 모듈 1차"
}
```

### verification (P6 런타임 대조 후 추가)

```json
"verification": {
  "status": "VERIFIED",
  "runtime_resource_id": "com.skt.tmap.ku.stage:id/btn_edit",
  "seen_in": ["fp_ab12cd"],
  "checked_at": "2026-11-10",
  "app_build": "11.2.0-stage-345"
}
```

| `status` | 의미 |
|---|---|
| `VERIFIED` | 실제 앱에서 확인, 식별자 일치 |
| `ID_MISMATCH` | 요소는 있으나 실제 resource-id가 다름 (`runtime_resource_id`에 실제 값) |
| `NOT_SEEN` | 화면은 방문했지만 요소가 안 보임 |
| `SCREEN_NOT_VISITED` | 런타임에서 화면 미방문 |
| `RUNTIME_ONLY` | 카탈로그에 없고 런타임에만 있음 (별도 목록) |

**스크립트 생성(P8)은 `VERIFIED` 요소를 우선 사용합니다.** `ID_MISMATCH`는 `runtime_resource_id`로 교체한 뒤 사용합니다.

| 필드 | 허용 값 |
|---|---|
| `policy_rules[].type` | `function` / `validation` / `permission` / `display` / `limit` / `exception` |
| `priority` | `P1`(핵심, 스모크) / `P2`(회귀) / `P3`(전체) |

| `status` | `draft` → `reviewed` → `approved` → `scripted` / `blocked_by_catalog` / `deprecated` |
| `steps[].action` | `tap` / `long_tap` / `input` / `clear` / `scroll_to` / `swipe` / `back` / `wait` / `assert_visible` |
| `expected[].check_type` | `element_visible` / `element_absent` / `text_equals` / `text_matches`(정규식) / `screen_is` / `count_gte` / `value_changed` / `vision` |

`check_type`이 `vision`이면 `description`에 사람이 읽을 수 있는 판정 기준을 씁니다.

## 8. 스크립트 구조 (P8)

```
qa-automation/
├── catalog/                 # 위 JSON 산출물
├── core/
│   ├── driver.py            # Appium 세션 생성 (capabilities는 환경변수)
│   ├── safety.py            # safe_tap / safe_input / 주행·결제 화면 감시   ← 필수
│   ├── waits.py             # 조건 대기
│   ├── evidence.py          # 실패 시 스크린샷·XML·logcat 저장
│   └── vision_check.py      # 비전 판정 (초기에는 skip)
├── flows/
│   └── entry.py             # open_screen(screen_id): deeplink → intent → ui_path 순서로 시도
├── pages/
│   └── favorite_list.py     # 화면별 Page Object
├── tests/
│   └── favorite/
│       └── test_tc_favorite_001.py
├── conftest.py
└── README.md
```

Page Object 예시 형식:

```python
class FavoriteListPage(BasePage):
    SCREEN_ID = "SCR_FAVORITE_LIST"

    # SCR_FAVORITE_LIST.btn_edit — view_common_header.xml:23 (VERIFIED)
    BTN_EDIT = Locator(id="com.skt.tmap.ku.stage:id/btn_edit", fallback_text="편집")

    def tap_edit(self):
        safe_tap(self.driver, self.BTN_EDIT)
```
